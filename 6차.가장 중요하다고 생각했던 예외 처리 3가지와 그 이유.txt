POST /orders의 user_id·product_id 유효성 검증:
주문은 사용자·상품 존재 여부를 전제로 하므로 필수 필드 누락 시 400, DB 존재 여부 확인 후 404를 던지게 해 데이터 무결성을 보장했습니다.

GET /products/:id의 ID 형식 검사와 미존재 응답:
정수가 아닌 값이 들어오면 곧바로 400으로 걸러 불필요한 쿼리를 막고, 실제 상품이 없을 때 404를 명확히 돌려 클라이언트가 재시도 전략을 세울 수 있습니다.

GET /orders/user/:userId의 주문 미존재 404 처리:
빈 배열을 성공으로 돌려보내면 “주문이 없는 것인지, 요청이 실패했는지” 구분이 어렵기 때문에, 해당 사용자의 주문이 없으면 404를 던져 API 소비자가 상태를 명확히 인지하도록 했습니다.
